RUST-EZE / DEPLOYMENT NOTES / NATIVE INTEL MAC / VERSION 4.2

Stand-alone Node.js, HTTPS, and local MySQL.

Rust-eze runs on an Intel Mac using macOS Ventura 13.7.8, Node.js, Fastify and an existing local MySQL server. The same Fastify process serves the Rust-eze website at /, React dashboard at /dashboard/, and REST API at /api/. It listens on HTTPS port 8123; Apache continues to serve your other sites independently on ports 80 and 443.

1. Install and build

Install Node.js 22 for macOS Intel x64, then from the Rust-eze directory:

cd /usr/local/var/www/appdevdesigndotcom/rusteze
npm install
npm run build
npm test
npm run test:date-format

2. Configure the local MySQL database

Rust-eze uses your existing MySQL server and the Rusteze schema. In config/database.env, set your actual application credentials:

MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_DATABASE=Rusteze
MYSQL_USER=rusteze
MYSQL_PASSWORD=YOUR_APPLICATION_PASSWORD

Use a dedicated MySQL application user. Do not publish your database password.

3. Configure the HTTPS listener

In the server's private .env file:

PORT=8123
API_HOST=0.0.0.0
CORS_ORIGIN=https://appdevdesign.com:8123
ADMIN_API_KEY=YOUR_OWN_ADMIN_API_KEY

The startup script reads config/tls.env, which reuses the same existing Sectigo certificate files that Apache uses, without changing Apache:

TLS_CERT_FILE=/usr/local/etc/openssl@3/certs/appdevdesigndotcom/2026/appdevdesign.com.crt
TLS_KEY_FILE=/usr/local/etc/openssl@3/certs/appdevdesigndotcom/2026/appdevdesign.com_key.txt
TLS_CHAIN_FILE=/usr/local/etc/openssl@3/certs/appdevdesigndotcom/2026/appdevdesign.com.ca-bundle

Fastify supplies the leaf certificate and intermediate CA chain to Node.js HTTPS; the matching private key stays on the Mac. Your Node.js service account must have secure read access to these files. Never move the private key into a public directory or weaken its permissions.

4. Start the service

bash scripts/start-macos.sh

Keep the terminal open while testing. For unattended startup, adapt the deployment/launchd/ service example. The existing router rule forwards external TCP 8123 to the Mac's TCP 8123. No Apache changes or new public 80/443 listeners are required.

5. Verify HTTPS and SDK functionality

curl --resolve appdevdesign.com:8123:127.0.0.1 \
  https://appdevdesign.com:8123/health

# From the Mac only, with your actual API key loaded:
curl -sS https://127.0.0.1:8123/api/plugins \
  -k -H "X-API-Key: $ADMIN_API_KEY"

Then open the website and the React dashboard. The browser-only playground needs no database; Live mode requires MySQL and a matching API key. For scripted API tests, download the Postman collection.

6. Certificate renewal and security

Rust-eze reads its TLS certificate on startup. After your certificate renews, restart Rust-eze to load the new certificate, key, and chain. If the versioned 2026 directory changes, update config/tls.env first.

The HTTPS site is public, but this demonstration also exposes administrative plugin operations behind an API key. The published Postman sample key is intentionally public: do not use it to protect real data. Keep secrets outside the public site and restrict access to admin endpoints as appropriate.

7. Timestamp display

The website and dashboard display timestamps in fixed MST (UTC−07:00), year-round, using MM/DD/YYYY HH:mm MST, for example 11/03/2026 22:23 MST. REST API responses retain ISO 8601 UTC timestamps for machine clients.

GraphQL workshop

Alongside the REST API, Rust-eze offers a live GraphQL endpoint at POST /graphql, secured by the same X-API-Key. Open GraphQL Workshop for query and mutation examples using the real MySQL and plugin registry.
